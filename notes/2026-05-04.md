## Bug Fixes

### Dark mode created even when disabled (semantic tokens)

**Problem:**
When semantic tokens were enabled but dark mode was off, the plugin still created a "Dark" mode inside the Semantics collection and populated it with light primitive values. This happened because the semantic block in `code.js` unconditionally added a Dark mode and set dark values for every token regardless of the `darkModeOn` setting.

**Root cause — `code.js` lines 151–158 (before fix):**
```js
// Ensure two modes: Light + Dark
if (semColl.modes.length < 2) {
  semColl.addMode('Dark');
}
semColl.renameMode(semColl.modes[0].modeId, 'Light');
semColl.renameMode(semColl.modes[1].modeId, 'Dark');
var semLightId = semColl.modes[0].modeId;
var semDarkId  = semColl.modes[1].modeId;
```
Dark alias values were also set unconditionally in the token loop.

**Fix:**
- When dark mode is off: Semantics collection gets only a single "Light" mode. Any pre-existing Dark mode (from a previous run) is removed via `semColl.removeMode()`.
- When dark mode is on: unchanged — adds both "Light" and "Dark" modes and populates both.
- `semDarkId` is set to `null` when dark is disabled; the dark alias assignment in the token loop is skipped entirely.

### Button and Link typography styles

Added `Button` and `Link` as two new categories in the Typography module.

**Behaviour:**
- **Button** — same sizes as Body per preset (L/M/S), one weight step bolder: `Medium` (500) instead of Body's `Regular` (400). Line height 150%.
- **Link** — identical to Body in size, weight (Regular 400), and line height (150%). Text decoration set to `UNDERLINE` on the Figma text style.

**Changes:**
- `code.js` — `sizeMaps`: added `Button` and `Link` rows (compact / standard / large) mirroring Body sizes.
- `code.js` — `weightFor`: `Button → 'Medium'`, `Link → 'Regular'`.
- `code.js` — `lineHeightFor`: both `→ 150`.
- `code.js` — text style creation: `style.textDecoration = cat === 'Link' ? 'UNDERLINE' : 'NONE'`.
- `code.js` — preview `typoOrder`: appended `'Button'` and `'Link'`.
- `ui.html` — `USE_TYPES`: added `'Button'` and `'Link'` badge options in font assignment UI.
- `ui.html` — `DEFAULT_FONTS`: Inter default now includes `Button: true, Link: true` alongside Body.

**Generated tokens (example — standard preset):**

### Color shade validation — implemented

Three validation cases in `validateColor` / `adjustColor` / `WARN_MESSAGES` (`ui.html`).

| Case | Trigger | Fix |
|------|---------|-----|
| `too-light` | `L > 65` | `L → 45`, `S → max(S, 65%)` |
| `too-dark` | `L < 22` | `L → 52`, `S → max(S, 65%)` |
| `too-pale` | `S < 15` (L in range); Neutral uses `NEUTRAL_PALE_S` | `S → 50`, L unchanged |

Both functions take a `colorKey` param to apply the correct threshold per color.

**too-pale** — replaced old `low-saturation` (S<5) case. Threshold is `S < 15` for all colors. Neutral (`colorKey === 'Neutral'`) uses `NEUTRAL_PALE_S = hexToHsl('#6B7280').s` (≈8.94%) so the default neutral sits exactly at the boundary and never triggers the warning. Only a neutral more desaturated than the default would fire it.

**too-dark threshold** settled at `L < 22` after iteration (started at 30, tested 20 and 25, landed at 22). Evidence: RGB(22, 106, 53) at L≈25.1% (`bugs/color shade fix/image 1.png`) — dark forest green that generates a usable shade scale and should not trigger.

**Neutral moved first** in the base colors list (was 3rd after Brand and Info).

### Semantic — text/icon primary/secondary/tertiary steps unified and spread wider

Text and icon steps were misaligned and gaps were too small. Unified both to the same values with bigger steps:

| Level | Before (text) | Before (icon) | After (both) |
|-------|--------------|---------------|--------------|
| primary | 0.89 | 0.89 | 0.89 |
| secondary | 0.67 | 0.56 | 0.56 |
| tertiary | 0.50 | 0.39 | 0.28 |

Gaps are now 0.33 and 0.28 — more consistent and visually distinct between levels.

### Semantic — surface/brand and border/brand get subtle + strong

`surface/brand` and `border/brand` now follow the same pattern as status surfaces/borders. `surface/brand/subtle` (0.00) and `surface/brand/strong` (0.33); `border/brand/subtle` (0.22) and `border/brand/strong` (0.50). Spec and WCAG pairs updated.

### Semantic — colored borders split into subtle + strong

Each status border (info, success, warning, error) now generates two tokens:

| Token | Step | Use |
|-------|------|-----|
| `border/info/subtle` | 0.22 | Light border for subtle containers |
| `border/info/strong` | 0.50 | Vivid border for outlined/active components |

Same pattern for success, warning, error. WCAG contrast pairs in spec updated to match (`border/*/subtle ↔ surface/*/subtle`, `border/*/strong ↔ surface/*/strong`).

### Semantic — colored surfaces split into subtle + strong

Each status surface (info, success, warning, error) now generates two tokens instead of one:

| Token | Step | Use |
|-------|------|-----|
| `surface/info/subtle` | 0.00 (lightest) | Alert backgrounds, tinted containers |
| `surface/info/strong` | 0.33 (medium) | Filled badges, chips, vivid surfaces |

Same pattern for success, warning, error. Changed in `buildSemanticTokens` (`code.js`) and spec (`claude.md`). The stylesheet renderer still works — it filters by `surface/` prefix which matches both variants.

### Semantic — bg tokens simplified to primary + inversed only

`bg/secondary` and `bg/tertiary` removed from `buildSemanticTokens` (`code.js`) and from spec (`claude.md`). Background group is now just `bg/primary` (lightest, #FCFCFC in light) and `bg/inversed` (darkest neutral step). Surface tokens cover the mid-level container/panel use cases.

### Semantic — bg/primary light set to 1% off-white

`buildLightShades` in `code.js` — neutral step 0 changed from pure white `{ r:1, g:1, b:1 }` (#FFFFFF) to `{ r:0.99, g:0.99, b:0.99 }` (#FCFCFC). `bg/primary` light aliases to neutral step 0, so it inherits this value automatically. `text/inversed` and `icon/inversed` also use step 0 but the difference is imperceptible for white text on dark backgrounds.

## Feature — Stylesheet frame generator

### Overview

When the **Stylesheet** checkbox is on (default: on), the plugin generates a "Token Stylesheet" page in Figma after writing all variables and styles. The page is cleared and rebuilt from scratch on every run.

### UI change (`ui.html`)

- Footer: added **Stylesheet** option to the right of the "Overwrite existing" row
- Uses a square checkbox (same style as module sidebar checkboxes) placed to the **right** of the label text, with right-aligned label
- `payload.stylesheet` boolean passed in the generate message

### Frames generated (`code.js` — `generateStylesheet`)

Six frames placed left-to-right with 40px gaps on the stylesheet page:

| Frame | Source | Contents |
|-------|--------|----------|
| **Colors** | Primitives collection | One row per color — label + horizontal 44×44 swatches, fills bound to variables |
| **Semantic Tokens** | Semantics collection | Vertical list per group (bg / surface / text / icon / border / action) — 16×16 swatches bound to variables, light mode values shown |
| **Spacing** | Spacing collection | Name · px value · proportional blue bar |
| **Typography** | Local text styles | Table: Style · Size · Weight · live "Aa" preview in the actual font (capped at 28px) |
| **Border Radius** | Border Radius collection | Row of 60×60 rounded rects with actual radius applied, labeled below |
| **Elevation** | Local effect styles | Row of 80×56 white cards with actual shadow effects applied, labeled below |

### Helper functions added to `code.js`

- `generateStylesheet(modules, moduleConfigs)` — entry point, manages page, calls sub-builders
- `ssColors` / `ssSemantics` / `ssSpacing` / `ssTypography` / `ssRadius` / `ssElevation` — per-module frame builders
- `_ssTxt` / `_ssRgb` / `_ssShell` / `_ssDivider` — shared layout helpers

### Variable binding

Primitive swatches use `boundVariables: { color: createVariableAlias(v) }` inside the fill paint object so swatches update when variables change. Semantic swatches do the same — Figma resolves aliases at render time per mode.
